## Read this before touching anything

Six questions were asked and answered during planning. They are recorded in
`NOC_PLAN.md` under *Questions this design has already been asked*. Do not
re-litigate them; the reasoning is non-obvious and was hard won:

1. Router work moves from `handler()` to `tick()` — four reasons.
2. VCs belong to the **router**, not the link.
3. `depth ≥ RT₀` applies **only at zero load**; congestion is measured, not validated.
4. Aggregates are not merely compressed events — some have no event-level footprint.
5. Detail is **regenerated by deterministic replay**, not stored.
6. A packet is an `Event` *in transit across the NoC* — a role, not a new object.

### 0.1 `schemaVersion` + three-outcome `loadModel` + `migrate.ts`

**Why this is first — a live data-loss path.** Verified:

- `loadModel` (`packages/host/src/writer/index.ts:261-299`) returns `null` for
  **both** "file absent" and "file corrupt/unparseable" (the shape check at :266
  and the bare `catch { return null }` at :297).
- Both callers do `loadModel(root) ?? EMPTY_MODEL` —
  `ide/src/extension.ts:257` and `app/electron/session.ts:78`.
- `writeModel` writes the sidecar unconditionally (`writer/index.ts:212-214`).

So a sidecar this build cannot read looks like a fresh project and is
**overwritten on the next write**. In a repo with no git.

Work:

1. Add `schemaVersion: number` to `AuthoringModel`
   (`packages/contracts/src/model.ts:189-192`). `EMPTY_MODEL` is at `:194`.
2. New **pure** module `packages/host/src/writer/migrate.ts` exporting
   `migrate(raw): {model, from}`. Move the three existing in-place migrations
   out of `loadModel` into it as `migrateV0` (they are: string `fabric` → array;
   `portBandwidth` number → `portBandwidthBits = n × 32`; legacy `IO.*` leaves →
   `io` direction). They are currently untestable because they live inside an
   fs-touching function.
3. Change the return type:
   ```ts
   type LoadResult =
     | { ok: true; model: AuthoringModel; migratedFrom?: number }
     | { ok: false; reason: 'absent' }
     | { ok: false; reason: 'newer'; version: number }   // REFUSE TO WRITE
     | { ok: false; reason: 'corrupt'; detail: string };
   ```
4. Write `iss_authored.model.v<n>.json.bak` **once**, before the first migration.
5. Update both callers to distinguish the four cases and surface `newer`/`corrupt`
   to the user instead of silently starting empty.
6. `ide/test/migrate.test.ts` using the **real** `robot_soc` and `sample`

Keep `writer/index.ts` the only fs-touching writer module.

### Demo sidecars (both have keys `['components','events']` only — no version)

```
robot_soc  R1.rules = [{fetchWord, 0x0..0x1000    → Memory4},
                       {fetchWord, 0x1000..0x3000 → Memory1}]   ← OVERLAP at 0x1000
robot_soc  Gen1.traffic = {period 4, burst 1, count 0, start 0, roundrobin,
                           addrLo 0x1000, addrHi 0x1fff, random}
robot_soc  R2 = {portBandwidthBits: 96, arbitration: 'weighted'}
sample     R1.rules = [{Out1ToMemory1Event → Memory1}]          ← no address bounds
```

Three consequences for the Stage 2 migration:

- The **overlap at `0x1000`** is resolved today by first-match. Interval
  subtraction reproduces it exactly: `{0x0, size 0x1001 → Memory4}` and
  `{0x1001, size 0x2000 → Memory1}`. Gen1 draws `[0x1000, 0x1fff]`, so `0x1000`
  → Memory4 and `0x1001..0x1fff` → Memory1 — identical behavior. Watch the
  off-by-one: `size = hi − lo + 1` in BigInt, **before** subtraction.
- **`R2` sets 96 bits**, so `flitBits` must divide it. `gcd` gives 32 →
  `widthFlits = 3` = exactly 96. Picking 128 would silently raise that link's
  bandwidth 33%.
- **sample's rule has no address bounds**, so it becomes a `setPortDestination`
  override, not a region. This is why the escape hatch must exist.

Also: robot_soc has `Gen1ToMemory2Event`, `Memory1ToMemory3Event` and others that
are consumed but covered by **no rule** — they bind ingress, raise
`unmatchedPort`, and drop at runtime. The demo is partly broken today; migration
is the moment to make it coherent.

### Traps

| Trap | Detail |
|---|---|
| **`npm test` at root runs only the `ide` workspace** | `app/test/*` needs `npm run test --workspace app`. Run both. |
| **Engine Makefile has no `mkdir -p $(@D)`** | `engine/Makefile:16` is `$(BUILD)/%.o: src/%.cpp`. Sources under `src/noc/` fail with "No such file or directory". **Keep `src/` flat.** Headers may nest (`-Iinclude`). |
| **`examples/pipeline.cpp` is in the `all` target** | Bare `make` breaks in Stage 1 (it uses `Cycle` at :100, `currentCycle()` at :106) even though `simulate()` calls `make build/libmicroarch.a` and still passes. |
| **New engine sources must be added to `SRCS`** | Currently `src/scheduler.cpp src/link.cpp src/router.cpp src/trace.cpp`. Not in `SRCS` = not in the archive. |
| **Canvas classes need a base rule in `styles.css`** | Otherwise they render only in Electron — this already happened to the heat overlay. |
| **New colours must use `var(--vscode-TOKEN, fallback)`** | 223 existing uses; `app/src/theme.css` remaps them, and there are 5 `[data-skin]` skins. |
| **Hand-owned `.cpp` tails carry `microarch::Cycle name(const microarch::Event&)`** | The writer cannot rewrite them. Keep the `Cycle` alias; emit a migration banner at 4e. |
| **`parser/facts.ts` drops facts in free functions** | Fabric config is sidecar-only and invisible to round-trip. Generate the address map into the harness **as data** (`static const microarch::Region kRegions[]`). |
| **Addresses are 0x-hex STRINGS compared as BigInt** | Never JS numbers. `parseAddr`/`formatAddr`/`ADDR_MAX` in `model.ts:252-266`. |
| **`svadapter.ts` is the most-forgotten coupling** | Under clock domains its `tick()` must clock on *its* domain's edge, and its VCD timescale must equal `tickPs`. |
| **`synthesize.ts` is the easy-to-miss trace path** | `run.ts:146-149` falls back to it when the trace is thin; it must emit the new tick/timebase shape too. |

## Stage map (detail in `NOC_PLAN.md`)

| Stage | What | Acceptance gate |
|---|---|---|
| **0** | Scaffolding — the 5 items above | tests green, no behavior change |
| **1** | Time model: `Tick`/`DomainCycle`, event-driven scheduler, timebase record | demo traces identical **up to a uniform ×1000** |
| **2** | Address map + tiles, pure TS, engine untouched | demo traces **byte-identical to Stage 1's** |
| **3** | Topology/VC/clock-domain authoring (inert config) + all validators + phase strip | every validator has a test; nothing gates |
| **4** | The NoC engine — sub-stages 4a–4f, cutover at 4e deletes `router.cpp` | see plan; 4c is the wormhole invariants |
| **5** | Analytics: interval aggregates + deterministic replay | run twice → byte-identical traces |
| **6** | UI completion + two-host parity | zero new `HostMsg`/`ViewMsg` variants |

**Ordering hazards:** the address map must land **before** the engine NoC (the NI
decodes against a NodeId table generated from the map). Stage 1's ×1000 trace
change and Stage 4e's port-order determinism fix must be **separate commits**, or
the diffs are unreviewable.
