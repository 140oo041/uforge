REPOSITORY FIELD GUIDE · START HERE

The code is the design. The run is the proof.

This repository is a microarchitecture and SoC design environment with two hosts, one React schematic, a host-neutral parse/write/run layer, and a cycle-accurate C++ engine. Its central loop is not “draw, then export.” The canvas edits real source, the source executes, and the resulting trace returns to the canvas.

The shortest useful mental model @iss/canvas emits an EditIntent. @iss/host validates it and regenerates only marker-owned source. The C++ engine executes that source and writes JSONL hops, metrics, and divergences. The same canvas plays those records back.

01 / ORIENT

What this codebase is actually doing

It is a structured editor over executable microarchitecture source, not a drawing tool with code generation bolted on afterward.

The read direction

C++ files are scanned into facts, facts are assembled into a Graph, and the sidecar augments the few concepts source alone cannot express cleanly: empty composites, labels, I/O roles, implementation choice, router topology, run settings, and layout.

The write direction

Canvas operations become typed EditIntent messages. A pure reducer updates the AuthoringModel; deterministic writers render marker-owned regions back into C++, SystemVerilog, headers, and a generated harness.

The execution direction

The host compiles the generated harness and blocks against engine/build/libmicroarch.a. Events move through real Links on a real scheduler; routers apply real queues, arbitration, bandwidth, and routing rules.

The evidence direction

The engine records each hop at send time, plus router metrics and divergences. The host parses that JSONL into a Trace; the canvas animates tokens, fills the pipeline, paints congestion, and anchors failures to blocks.

Source of truth is deliberately split by meaning. Executable structure lives in source. Authoring state that cannot live there without distortion lives in iss_authored.model.json. Pure view state lives in iss_layout.json. Run inputs live in iss_run.json. Architectural intent lives in iss_spec.json.

Three models you should not conflate

The generated block's wire(Registry&) method resolves the destination by full dot-path. This is why a wire is visible as Tier-1 “wired” truth when the source is parsed again.

The project is reparsed immediately

The per-file parser cache extracts only changed facts, then pure assembly reconstructs the graph. In VS Code, unsaved documents arrive as overlays on a 120 ms debounce; a parse failure preserves the last good graph and reports the error.

packages/host/src/project/graphStore.ts · parser/index.ts

The same canvas receives substantiated state

The host augments the parsed graph with sidecar-only state and posts a new HostMsg. The UI does not optimistically become a source editor; it waits for the model it can substantiate.

The marker contract

// === ISS-AUTHORED:BEGIN — generated by the ISS canvas. Edit via the canvas, not by hand. ===
// This region may be replaced deterministically.
// === ISS-AUTHORED:END ===

// Everything outside/below the markers is hand-owned and preserved.
Do not put hand-written behavior inside the marker region. The writer is designed to replace it. For routers, SV twins, and custom traffic generators, the intended extension point is the tail below the end marker.
04 / RUN

Follow Run into execution and back

The normal path builds and executes the design for real. Synthetic trace generation is a clearly reported preview fallback only when a successful run yields no hops.

The host gates invalid fabric

deriveFabric() runs before compilation. Cross-top point-to-point wires are hard errors and block Run. Rule ambiguities and missing matches are warnings because the runtime can drop and report them honestly.

The harness is regenerated

emitHarness() includes every leaf, creates one Link per out-port, instantiates blocks, registers full IDs, invokes each block's wire(), configures routers, installs trace sinks, selects entries, and seeds tokens.

SV leaves are verilated if selected

Each impl: 'sv' leaf is linted and compiled under a unique prefix. A cheap mtime cache avoids repeating Verilator work when the twin has not changed.

The host compiles one executable

g++ -std=c++17 -O2 compiles the generated harness, any hand-written translation units, optional Verilated sources/runtime, and libmicroarch.a into build/design.

The scheduler runs the cycle budget

The harness seeds configured or auto-detected entry leaves, calls scheduler.runFor(maxCycles), and writes iss_trace.jsonl as events are sent and router state changes.

The host parses evidence

parseTrace() resolves engine names back to graph IDs and separates hop, metric, and divergence records. It also records the actual clock stop so in-flight-but-undelivered events remain visible.

The canvas derives playback views

Token timelines, positions, occupancy, congestion, pipeline cells, latency histograms, wave lanes, and problem entries are all projections over the returned trace—not simulated UI decoration.

Trace record shapes

{"token":7,"from":"CPU0.EX","to":"CPU0.MEM",
 "event":"ExecEvent","depart":4,"arrive":5}

{"metric":"qdepth","cycle":12,"component":"R1",
 "port":"Memory1","value":3}

{"diverge":true,"cycle":14,"component":"EX",
 "token":7,"detail":"x5 mismatch","kind":"cosim"}

Verify is a second path

verify() invokes xverify --json --ref sail|stub. Divergence order is associated with the last trace hop for that token, so an architectural mismatch lands on a useful block and cycle.

If Sail is requested but its driver is unavailable, the code falls back to stub and logs that fact. Missing xverify or program input skips verification visibly rather than fabricating a verdict.

08 / EXECUTE

The C++ engine in one cycle

The engine is small by design: event delivery, two-phase clocking, named wiring, routing, and evidence sinks. Generated designs include its public umbrella header or compatibility shims.

1 · DISPATCH

Drain every event scheduled for the current cycle in FIFO order. A handler may send zero-latency events back into the same cycle; dispatch keeps draining until the bucket is empty.

2 · SETTLE

Call settle(cycle) on clocked components until none requests another delta cycle. A safety limit throws if combinational logic never quiesces.

3 · TICK

Call tick(cycle) once on every clocked component, then advance the clock. A zero-latency send during Tick lands next cycle, preserving synchronous causality.

TypeContract
ComponentA named block with required handler(Event&) and optional settle/tick phases.
EventMove-only message carrying type, delivery cycle, stable token, destination, fabric destination, origin, address, and width in bits.
LinkDirected connection with latency. It stamps origin/token context, schedules delivery, records a hop, can divert to a shadow tap, or interpose a router.
SchedulerMap-based calendar, token minting, active event ownership, phase-aware delivery, clocked components, and hop/divergence/metric sinks.
RegistryString-to-component lookup that lets each generated block contain its own configureOut truth.
RouterOrdered match rules, destination routes, queues, bandwidth credit, arbitration, latency models, drop/stall policy, and metrics.
Trace writerJSONL serialization for hop, divergence, and metric records.

Token propagation

Scheduler::seed() mints a token. During handler dispatch, the scheduler exposes that token as active context. Every event sent by a Link while handling the current event inherits it, which lets multiple hops form a single transaction timeline without coupling event subclasses to pipeline semantics.

Compatibility layer

The engine/include/infra/*.h headers hoist microarch::Component, Event, Link, and Scheduler into the global namespace. Generated sample blocks currently use these shims; new hand-written code may include microarch/engine.hpp directly.

09 / ROUTE

Top-level dataflow is rule-based fabric

Point-to-point wires are valid inside a top-level unit. Traffic between top-level units must enter routers and be resolved by ordered forwarding rules.

Why the hard boundary exists: an authored wire has one destination; an SoC fabric routes packets by type and address. Allowing a direct cross-top wire would bypass contention, router latency, queueing, arbitration, and address decode—the exact behavior this tool exists to explore.

Derivation algorithm

  1. Report every cross-top point-to-point wire as a blocking crossTopWire error.
  2. Find dangling, message-carrying out-ports under attached top-level units.
  3. Choose an ingress router, preferring an attachment with a matching rule.
  4. Expand each authored rule by known ingress messages, resolve its destination leaf, and find the shortest router trunk path with BFS.
  5. Emit concrete addMatchRule, addRoute, setRouteLatency, and routeVia calls into the harness.
  6. Expose derived top-to-top ghost edges and diagnostics to the canvas.

Packet matching

Rules are ordered and first-match-wins. A rule may constrain message type, inclusive address lower/upper bounds, or neither. A packet with no match is dropped and emitted as a drop divergence; the simulation continues.

Packet cost

Bandwidth is bits per output port per cycle. A packet costs its event width: a 512-bit packet on a 128-bit/cycle output occupies four cycles, while several narrow packets can share one cycle.

Queue policy

Unbounded is the default. A bounded full queue either stalls the packet by rescheduling it at the router next cycle or drops it and records a divergence.

Arbitration

FIFO preserves arrival order; round-robin alternates origins; fixed priority drains lower rank first; weighted DRR grants bit-quantum proportional to origin weight.

Router evidence

Routers emit change-only queue depth (qdepth), per-cycle packet flow (flow), forwarded bits (bits), and full-queue retries (stall). These records feed the canvas heat overlay and METRICS tab without a router-specific UI simulation.

10 / CO-SIM

SystemVerilog twins execute inside the same timeline

Every ordinary leaf can have a generated-port / hand-behavior SV twin. Selecting impl: 'sv' replaces that C++ instance with a Verilated adapter in the harness.

Twin surface is generated

The marker-owned SV region contains the module header, clock/reset, input valid strobes and fields for consumed events, and output valid strobes and fields for out-ports. The RTL body below the marker is yours.

Verilator builds a unique model

Each leaf gets a prefix such as V_CPU0_DE and its own build/verilated/<id> directory, so duplicated composites can coexist.

The adapter translates both directions

handler() latches engine events into RTL inputs. tick() drives a full clock pulse, reads valid outputs, converts them back to engine events, and sends them through the leaf's normal Links.

VCD shares the playhead

Optional per-block VCDs are written to build/waves/. Host parsing turns them into WaveDocs; the WAVES tab uses the same cycle playhead as trace and pipeline views.

Opt-in SV ↔ C++ divergence checking

A checked adapter also instantiates the real C++ block as a shadow. Its output Links are diverted into expectation buffers and never enter the design or trace. Actual SV emissions are compared field-by-field against expectations keyed by token; mismatches, SV-only outputs, and C++-only outputs become cosim divergences.

Documented limit: token attribution uses an input FIFO and comparison is per-token. It is exact for in-order transaction flows, including fan-out, but heuristic for internally reordering pipelines.

11 / AUTHOR

Hand-written C++ that the canvas understands

This section incorporates the repository's new CPP_API.md reference: the public engine surface, exact parser-recognized forms, marker ownership by file type, recipes, and verified build traps.

The recognized slice is not a language restriction. Ordinary C++ outside it still compiles and runs. The slice only determines how much structure the parser can project back onto the canvas.

Include surface

#include "microarch/engine.hpp"  // preferred for new hand-written code
#include "iss_events.h"          // the project's generated message vocabulary

Generated blocks currently include the compatibility shims under engine/include/infra/, which alias the same engine types into the global namespace. Both styles work; new hand-authored code should prefer the umbrella header and explicit microarch:: qualification.

Parser attribution rules

  • Prefer registry.find("Full.Id"); it names identity directly.
  • Facts in standalone free functions are ignored because blocks own their wiring.
  • Declarations and definitions can contribute facts from different files.
  • The scanner reads C/C++ source under inc/ and src/, skipping build outputs.
  • Tier-1 explicit wiring always wins over message-based inference.

File-specific marker ownership

  • Leaf C++: generated class; surrounding text is hand-owned.
  • Router C++: generated region opens the class; hand latency models and closing }; live below END.
  • Traffic generator, generated mode: entire file is canvas-owned.
  • Traffic generator, custom mode: generated class head; hand-owned tick() tail.
  • SV twin: generated module header/ports; hand-owned behavior and endmodule.
  • Harness: rewritten as a whole despite carrying markers.

Recipe: a hand-written block that remains legible

#pragma once
#include "microarch/engine.hpp"
#include "iss_events.h"

class Probe : public microarch::Component {
  public:
    explicit Probe(microarch::Link* out = nullptr)
        : Component("Probe"), out_(out) {}

    void handler(microarch::Event& ev) override {
        if (ev.type() == "PingEvent") {          // consume: recognized
            ++hits_;
            if (out_ && out_->connected()) {
                auto reply = std::make_unique<PongEvent>();
                out_->send(std::move(reply));    // emit: recognized
            }
        }
    }

  private:
    microarch::Link* out_;                        // out-port: recognized
    uint32_t hits_ = 0;                           // state: recognized
};

With one other PongEvent consumer, the parser shows Probe as a hand-written leaf with one consumed message, one out-port, one state variable, and an inferred edge to that consumer. Its dashed border and refused canvas edits communicate that the sidecar does not own it.

Recipe: addressed traffic

auto ev = std::make_unique<ReadEvent>();
ev->addr = 0x8000'0000;
out_->send(std::move(ev));

Router rules match that uint64 address against their inclusive ranges.

Recipe: originate on a clock edge

void tick(microarch::Cycle cycle) override {
    if (cycle % 4) return;
    auto ev = std::make_unique<ReqEvent>();
    ev->token = scheduler_.mintToken();
    out_->send(std::move(ev));
}

There is no active handler token during Tick, so the originator mints one explicitly and must be registered as clocked.

What actually becomes a translation unit

Run always compiles src/iss_main_gen.cpp. Generated block files are inline classes included by that harness, not separate translation units. The host separately compiles only top-level src/*.cpp files with no marker.

Parsed does not mean executable. A marker-free hand-written class can be parsed and drawn on the canvas, but the generated harness constructs, wires, and clocks only components present in iss_authored.model.json. Seeing a block is proof that the parser recognized it—not proof that a run instantiates it.
Two verified traps: a marker-free hand-written file under src/CPU0/ is neither compiled as a top-level translation unit nor automatically included by the harness. Also, adding a canvas block with the same ID as a hand-written class does not adopt it—the writer appends a generated class and causes a duplicate definition. Keep hand-written TUs at top-level or include them explicitly, and convert/adopt ownership deliberately.

Editing rules worth keeping beside the code

  • Inside markers, edit through the canvas. Below END, use ordinary C++/SV.
  • Component("<id>") is identity. Use the inspector for cosmetic labels.
  • Generated constructors take out-links positionally in writer order.
  • setLink(const char*, Link*) is the stable late-injection surface.
  • Describe exceptional packet widths in the Messages view; do not patch generated iss_events.h.
  • Serialize uint64 addresses as hex strings when data crosses into JavaScript.

14 / PLANNED

Roadmap: a flit-level NoC over the IP canvas

The plan at glimmering-foraging-elephant.md proposes a major transport redesign. Everything in this chapter is planned work—not behavior present in the repository today.

Status boundary: current code uses whole Event packets, one global-cycle Scheduler, per-router ordered forwarding rules, and queue-local stall/drop behavior. The proposed system replaces inter-tile transport while preserving event-driven handler() semantics inside each tile.

Why the current transport is not enough

Current limitationConsequencePlanned answer
No real flitsEvent::bits meters a port, but a packet is never fragmented and cannot occupy several routers at once. Load-dependent latency is too optimistic.Head/body/tail wormhole flits, virtual channels, and synchronous channels.
No upstream backpressure“Stall” reschedules a packet at the same router; the sender never sees downstream capacity.Reverse credits sized from the downstream router's declared VC buffers.
One clockA slow peripheral tile and a fast core tile tick together; frequency and CDC latency cannot be modeled.Fine integer tick timebase plus authored clock domains with period, phase, and synchronizer depth.
No global address mapRanges are repeated per router, so overlaps/gaps are not globally validated and first-match order can hide mistakes.One non-overlapping design-wide region map decoded at network injection.
Destination guessed by message consumersTwo banks inside one tile can be indistinguishable.Each region explicitly targets both a tile and an existing io:'in' interface pin.

The target split

ROOT · NoC stage

Synchronous transport

Top-level tiles, routers, channels, address regions, clock domains, virtual networks, and topology. Flits move only on domain edges through evaluate/commit.

DRILL-IN · IP stage

Event-driven microarchitecture

Existing leaf blocks and point-to-point Links remain event-driven. handler() stays the IP contract, protecting authored block behavior.

SEAM · NetworkInterface

Adapter between worlds

The NI packetizes Events into flits, injects and ejects them, performs global address decode, snaps across clock domains, and returns the Event payload at the tail.

Eight settled decisions

  1. Wormhole transport with virtual channels: the head allocates route and VC; the tail releases them; credits enforce real downstream capacity.
  2. VCs belong to routers: heterogeneous counts are legal, while vcCount ≥ vnetCount is a validated fabric invariant.
  3. Integer physical time: derived ps-scale ticks plus per-domain frequency/phase. Latencies remain authored in domain cycles; CDC delay emerges by snapping to the destination edge.
  4. Global address map: the NI stamps a dense destination node; router forwarding tables are derived, with per-region route override as the escape hatch.
  5. Phases guide but never gate: readiness is visible and navigable, but the UI never locks work.
  6. Flits stay off the calendar: synchronous channels move them on ticks. The event calendar is touched only at NI injection/ejection.
  7. Evaluate then commit: routers read current state, compute next state, then commit together. Iteration order cannot permit two hops in one cycle.
  8. Two fidelity modes: fast store-and-forward packets and accurate wormhole/VC/credit execution share one model, trace schema, and metric vocabulary.

Migration is a first-class safety feature

Today loadModel() returns null for both absent and corrupt sidecars, and both hosts fall back to an empty model. The plan treats that as a live data-loss path: loading becomes a discriminated result for success, absent, newer schema, or corruption; newer/corrupt projects refuse writes. A pure migrate.ts produces a report and the writer creates one versioned backup before the first migration.

The real robot_soc overlap at 0x1000 is migrated by interval-subtracting later rules against earlier ones, preserving current first-match semantics as a non-overlapping map. Rules without bounds become explicit per-port destination overrides. Old bandwidths derive flitBits with GCD so 96 bits/cycle stays 96 rather than silently rounding up.

Trace contract after cutover

  • A mandatory first record declares tickPs and all domain periods/phases/synchronizer depths.
  • Trace.cycles/ranCycles are renamed to ticks/ranTicks; no compatibility alias is kept because a silent scale error is worse than a compile error.
  • Packet-level hops retain depart/arrive meaning for tokenAnim.ts, and gain packet bits, vnet, and flit count.
  • Per-flit trace is opt-in, time-windowed, record-capped, and emits a truncated record when capped.
  • Histogram records stay separate from scalar metrics so existing metric parsing remains structurally valid.
  • New metrics include vcOcc, credStall, vcStall, injectDepth, and head-of-line blocking; compatible flow/bits/stall/qdepth names survive.

Planned UI without host drift

Memory as a map

A new Memory tab renders regions as contiguous address bars with target tile and interface. Gaps and overlaps are spatial evidence, not validation text hidden in a form.

Fabric as derived truth

Router inspectors lose editable forwarding rules and gain VCs plus a read-only next-hop table that explains each path. Route overrides move to regions.

Topology remains authored

A one-shot topology picker expands a macro intent into ordinary routers, peers, and attachments so layout, source files, inspector state, and undo remain normal.

Two-host discipline holds

Clock domains, vnets, flit width, tile class, address regions, and fidelity all use existing edit intents or setRunConfig. The target is zero new HostMsg/ViewMsg variants.

Ordering hazards and proof

  • Land the address map before the engine NoC; otherwise the NI needs a throwaway destination decoder.
  • Keep the Stage-1 time scaling and Stage-4 port-order determinism changes in separate commits so trace diffs stay reviewable.
  • Update SV adapter clock edges and VCD timescale together; update the synthetic-trace fallback or it silently emits an incompatible time shape.
  • Dense PortIds must replace pointer-keyed router maps in the same change as evaluate/commit, or metrics remain allocator-order-dependent.
  • Do not poll traffic generators every tick once the scheduler can jump time; schedule bursts on the calendar.
End-to-end proof target: generate a 2×2 mesh, run a 2 GHz CPU tile and 60 MHz USB tile in different domains, map two regions to two interfaces of the same memory tile, use accurate mode, and verify correct bank delivery, visible CDC latency, and a real offered-load latency knee accompanied by rising credit stalls.

16 / GUARD

Invariants that explain surprising code

Most of the architecture becomes obvious once these rules are treated as non-negotiable.

Exactly one shared canvas
Do not add a second graph editor for Electron or a host-specific copy of interaction logic. The injected HostTransport and useDesignSession() exist to keep behavior byte-identical across hosts.
Every structural edit leaves as an EditIntent
The webview/renderer is not allowed to write files or become a text editor. Hosts validate and persist; the view asks.
Generated regions are replaceable; everything else survives
spliceRegion() is the preservation boundary. A feature that needs hand-written behavior must provide a tail or another explicit ownership mode.
Full dot-path IDs are engine identity
CPU0.IF maps to the directory src/CPU0/IF.cpp, namespace CPU0, type CPU0::IF, registry key CPU0.IF, and canvas hierarchy. Display labels may differ.
Cross-top wires are invalid
Wires model direct intra-unit structure. Router rules model top-level dataflow. Do not “fix” the guard without replacing fabric semantics end-to-end.
A hop is recorded at send time
A hop can have an arrival at or beyond the actual clock stop. Those records mean “sent but never delivered,” and ranCycles exists so the UI can say exactly that.
Failures stay visible
Unknown destinations become unresolved links, no consumers become stubs, parse failure retains the previous graph plus an error, fabric warnings become drops, and missing verification dependencies become explicit notices.
Packet widths and addresses need exact representations
Bandwidth is in bits; event widths derive from field types unless overridden. Host addresses are strings/BigInt, never floating-point numbers.
Build outputs must not parse as authored blocks
The parser skips build/ and out/; generated SV adapters deliberately live under build so they cannot masquerade as design components.
17 / TERMS

Local vocabulary

These words have precise meanings in the code and UI.

authored
Owned by the canvas/write model and usually substantiated by generated code inside markers.
hand-owned
User code outside markers. The writer must preserve it.
leaf
An executable component with one .cpp file and usually an SV twin.
composite
A hierarchy/grouping node represented by a directory plus C++ namespace; it has no runtime instance.
port
A named outgoing Link* on a leaf, paired with a message, latency, and optional destination.
wired
An explicit configureOut destination found in source.
inferred
No explicit destination, but exactly one other component consumes the emitted message.
stub
An out-port with no usable consumer or no detected send; displayed as dangling.
routed
A destination-less port entering the fabric, where ordered rules resolve each packet.
token
Stable transaction ID minted at seed/origin and inherited across downstream events.
hop
One Link send record: token, endpoints, message, departure, arrival, and optional address.
trace
The parsed collection of hops, metrics, divergences, and clock bounds from one run.
fabric
Router attachments, trunks, ordered forwarding rules, and their derived runtime routes.
SPEC
Layer-1 architectural contract: types, state, I/O, operations, encodings, and oracle status.
SV twin
A per-leaf SystemVerilog implementation with generated ports and hand-authored behavior.
divergence
A localized mismatch or loss record with architectural, cosim, synthetic, or drop provenance.
