# Working with the C++ — API reference

The canvas is a structured editor over a *recognized slice* of ordinary C++.
The code is the source of truth: nothing the canvas shows exists only in a
database, and nothing you write by hand is off-limits to the parser. That makes
two contracts worth knowing before you touch a `.cpp`:

1. **The marker contract** — which text the canvas may rewrite, and which text
   is yours forever.
2. **The recognized slice** — the exact C++ forms the parser reads back, so a
   hand-written block shows up on the canvas with its ports, its messages and
   its state instead of as an opaque box.

Everything below is the engine as it actually is (`engine/include/microarch/`),
not an idealized version of it.

---

## 1. Project layout

```
<project>/
├── inc/
│   ├── iss_events.h        generated — every message class
│   └── iss_arch.h          generated — spec types, signal enums, `arch` state
├── src/
│   ├── <Leaf>.cpp          one file per top-level block
│   ├── <Composite>/        composites are directories = C++ namespaces
│   │   └── <Leaf>.cpp        → namespace CPU0 { class IF … }, id "CPU0.IF"
│   ├── <Router>.cpp        one per router; your latency models live here
│   ├── <Leaf>.sv           SystemVerilog twin (optional, co-simulated)
│   └── iss_main_gen.cpp    generated harness — main(), links, wiring, run loop
├── iss_authored.model.json the sidecar: what the canvas authored
├── iss_layout.json         block positions (cosmetic)
└── build/design            the compiled binary
```

A block's **id** is its dot-path (`CPU0.IF`), which is its namespace path plus
class name. That id is the engine identity: `Component("CPU0.IF")`. The display
label in the inspector is a separate, cosmetic thing kept in the sidecar: a
`Component("…")` string that *differs* from the id is read back as that label,
while one that equals the id is identity and the canvas shows the leaf name
(§7).

## 2. The marker contract

```cpp
// === ISS-AUTHORED:BEGIN — generated by the ISS canvas. Edit via the canvas, not by hand. ===
   ...canvas-owned. Rewritten in full on every edit. Your changes here are lost.
// === ISS-AUTHORED:END ===
   ...yours. Byte-preserved forever.
```

The canvas only ever splices the text *between* the markers
(`packages/host/src/writer/markers.ts`). What that means per file type:

| File | Generated region | Hand-owned |
|---|---|---|
| `src/<Leaf>.cpp` | the whole class | anything above BEGIN / below END |
| `src/<Router>.cpp` | ctor + `flat()` default; **the class stays open across END** | latency models + the closing `};` |
| `src/<Gen>.cpp` (traffic, *generated* mode) | the whole file, prologue included | nothing — the file is canvas-owned |
| `src/<Gen>.cpp` (traffic, *custom* mode) | class head only | `tick()` and the closing brace |
| `src/<Leaf>.sv` | `module` header + port list | the behavioral body + `endmodule` |
| `inc/iss_events.h`, `inc/iss_arch.h` | the whole body | anything outside the markers |
| `src/iss_main_gen.cpp` | **the entire file** — it carries markers but is rewritten whole, not spliced | nothing |

A file with **no markers at all is never rewritten** — it is a hand-written
file, and the canvas treats it as read-only (dashed border, "hand-written"
badge, edits refused).

> **The router trick.** In `src/<R>.cpp` the generated region opens
> `class R2 : public microarch::Router {` and does *not* close it. Your latency
> models sit below the END marker inside that same class body, followed by the
> `};`. That is why they survive regeneration.

## 3. Engine API

Include the umbrella header — it pulls in everything:

```cpp
#include "microarch/engine.hpp"     // component, event, link, registry,
                                     // router, scheduler, trace
```

Generated blocks instead include the legacy shims `infra/component.h`,
`infra/event.h`, `infra/link.h`, which hoist the same types into the global
namespace (`using Component = microarch::Component;`). Both work; new
hand-written code should prefer `microarch/engine.hpp` and qualify explicitly.

### 3.1 `Component` — a block

```cpp
class Component {
    explicit Component(std::string name);            // name == the engine id
    const std::string& name() const noexcept;

    virtual void handler(Event& event) = 0;          // one call per delivered event
    virtual bool settle(Cycle cycle);                // combinational phase; true = another delta
    virtual void tick(Cycle cycle);                  // clock edge, after settle
};
```

Non-copyable. Each cycle runs **dispatch → settle → tick**; `settle()` may
request more delta-cycles within the same cycle (bounded by the scheduler's
`maxDeltaCycles`, default 1024). Only components registered with
`Scheduler::addClocked` get `settle`/`tick`.

### 3.2 `Event` — a packet

```cpp
class Event {
    explicit Event(std::string type = "Event");
    const std::string& type() const noexcept;        // what the IDE keys edges on

    Cycle       cycle    = 0;        // delivery cycle   (filled by send/schedule)
    TokenId     token    = no_token; // transaction id   (inherited from the in-flight event)
    Component*  dest     = nullptr;  // destination      (filled by send/schedule)
    std::string finalDest;           // fabric target    (stamped by routeVia'd links)
    std::string origin;              // first sender     (stamped on hop 1; routers arbitrate on it)
    std::uint64_t addr   = 0;        // transaction address; router rules match on it
    std::uint32_t bits   = default_event_bits;  // WIRE WIDTH — see §3.6
};
```

Define a message by deriving and passing a type name:

```cpp
class FillEvent : public Event {
  public:
    FillEvent() : Event("FillEvent") { bits = 576; }   // 8×uint64_t + uint64_t tag
    uint64_t data[8] = {};
    uint64_t tag = 0;
};
```

In practice you do **not** hand-write this: `inc/iss_events.h` is generated from
the ✉ Messages view, and the `bits` value is derived there from the declared
field types. Write messages by hand only in a project you are not authoring
through the canvas.

### 3.3 `Link` — a wire

```cpp
class Link {
    explicit Link(Scheduler&, Cycle latencyCycles = 1);
    Link(Scheduler&, Component& source, Component& destination, Cycle latency = 1);

    void configureIn(Component* source) noexcept;     // who sends
    void configureOut(Component* destination) noexcept; // who receives  ← parsed as a wire
    void connect(Component& source, Component& destination) noexcept;

    Component* source() const noexcept;
    Component* destination() const noexcept;
    bool connected() const noexcept;    // destination OR a via router — the send guard

    Cycle latency = 1;                  // public; `link->latency = N` is parsed
    void setLatency(Cycle) noexcept;

    void send(std::unique_ptr<Event> event);          // throws std::logic_error if unrouted
    template <typename EventT, typename... Args> void send(Args&&...);

    void routeVia(Component& via, std::string finalDest);  // fabric, destination pre-resolved
    void routeVia(Component& via);                         // fabric, router resolves by rule
    void divert(EventTap tap) noexcept;                    // shadow capture (co-sim)
};
```

`send()` schedules delivery at `scheduler.deliveryCycle(latency)` and emits a
`HopRecord` when a hop sink is installed — that is the seam the trace animation
rides. **Always guard on `connected()`**, not `destination()`: a fabric-routed
port intentionally has no destination.

```cpp
if (out && out->connected()) {
    auto ev = std::make_unique<FillEvent>();
    ev->addr = 0x1000;
    out->send(std::move(ev));
}
```

### 3.4 `Registry` — wiring by name

```cpp
class Registry {
    void add(Component&);                          // keyed by name()
    void add(std::string name, Component&);        // keyed explicitly (harness uses the id)
    Component* find(const std::string&) const noexcept;   // nullptr when absent
    Component& at(const std::string&) const;              // throws when absent
};
```

This is what lets a *block* own its wiring rather than the harness:

```cpp
void wire(microarch::Registry& registry) {
    if (out) out->configureOut(registry.find("CPU0.DE"));   // ← Tier-1 'wired' edge
}
```

### 3.5 `Scheduler` — the clock

```cpp
Cycle currentCycle() const noexcept;
Phase phase() const noexcept;                     // Idle | Dispatch | Settle | Tick
std::size_t pending() const noexcept;

void schedule(std::unique_ptr<Event>, Component& dest, Cycle at);   // throws if `at` is past
void scheduleNow(std::unique_ptr<Event>, Component& dest);

TokenId seed(std::unique_ptr<Event>, Component& dest, Cycle at);    // mints a fresh token
template <typename EventT, typename... Args>
TokenId seed(Component& dest, Cycle at, Args&&...);
TokenId seedNow(...);
TokenId mintToken() noexcept;                     // a token with no event (traffic gens)

Cycle deliveryCycle(Cycle latency) const noexcept;// phase-aware: a 0-latency Tick send
                                                  // still lands next cycle
void addClocked(Component&);                      // opt into settle()/tick()
void removeClocked(Component&);

void setHopSink(HopSink);                         // trace seams
void setDivergenceSink(DivergenceSink);
void setMetricSink(MetricSink);
void reportDivergence(const Component&, TokenId, std::string detail, std::string kind = "");
void reportMetric(const Component&, std::string metric, std::string port, std::uint64_t value);

TokenId activeToken() const noexcept;             // in-flight transaction (no_token outside a handler)
void fillToken(Event&) const noexcept;
std::unique_ptr<Event> releaseActiveEvent() noexcept;  // take ownership of the dispatched event

void runFor(Cycle count);
void runUntil(Cycle endExclusive);
```

Two subtleties that bite:

- **Token inheritance is automatic.** Any event a handler sends inherits the
  in-flight token, so a trace threads into per-transaction chains for free. A
  component that originates traffic from its own `tick()` has no in-flight
  token — call `mintToken()` and assign `ev->token` yourself.
- **`releaseActiveEvent()` is how you keep an event.** By default the dispatch
  loop frees the event after `handler()` returns. A handler that parks a packet
  (as `Router` does) must take ownership first; it returns null outside
  `Dispatch` or if something already took it.

### 3.6 `Router` — the fabric, and what a packet costs

```cpp
Router(std::string name, Scheduler&, Cycle hopLatency = 1);

void addMatchRule(std::string message, std::uint64_t lo, std::uint64_t hi, std::string finalDest);
void addMatchRule(std::string message, std::string finalDest);   // any address
void addRoute(const std::string& finalDest, Component& nextHop);
void setRouteLatency(const std::string& finalDest, LatencyModel);

void setArbitration(Arbitration) noexcept;        // Fifo | RoundRobin | FixedPriority | Weighted
void setSourceWeight(const std::string& origin, std::uint32_t);   // throws on 0
void setSourcePriority(const std::string& origin, std::uint32_t); // lower drains first

void setBandwidth(std::uint32_t bitsPerPortPerCycle);             // BITS, not packets
void setPortBandwidth(const std::string& nextHop, std::uint32_t bitsPerCycle);
void setQueueCapacity(std::size_t perPortCapacity) noexcept;      // 0 = unbounded
void setFullPolicy(FullPolicy) noexcept;          // Stall (default) | Drop

std::size_t pendingCount() const noexcept;
```

**Bandwidth is bits per output port per cycle** (default
`default_event_bits` = 32, i.e. one ordinary word). A packet costs
`Event::bits`, so a 512-bit packet on a 128 b/cy port occupies it for four
cycles while several narrow packets share one. Unspent budget carries while the
port has a backlog and is zeroed when it drains, so an idle port cannot bank
bandwidth for a burst. `Weighted` is bit-quantum deficit round-robin: equal
weights split *bits*, so an origin sending 4×-wide packets gets a quarter as
many of them.

Ingress resolution: a packet arriving with an empty `finalDest` takes the
**first** matching rule (message type + inclusive `[lo, hi]` address range).
No match → dropped and reported through the divergence sink with kind `"drop"`.
The simulation continues; real fabrics surface decode errors, they don't halt.

**Latency models** are ordinary member functions on your router subclass:

```cpp
// below the END marker in src/R2.cpp — survives regeneration
microarch::Cycle congested(const microarch::Event& event) {
    return event.token % 4 == 0 ? 6 : 2;
}
```

Signature must be exactly `Cycle name(const Event&)` (optionally
`microarch::`-qualified) for the parser to list it in the router's inspector.
Assign one per routed wire in the wire panel; unassigned wires use `flat()`.

### 3.7 Trace records

```cpp
struct HopRecord        { from, to, event, token, depart, arrive, addr; };
struct DivergenceRecord { component, detail, token, cycle, kind; };
struct MetricRecord     { metric, component, port, cycle, value; };
```

Metric kinds emitted today, all by `Router`: `qdepth` (settled per-port depth,
change-only), `flow` (packets forwarded this cycle), `bits` (their total
width), `stall` (full-queue retries). `JsonlTraceWriter` turns all three into
the JSONL the IDE reads; `addr` is written as a **hex string**, never a number,
because uint64 does not survive JavaScript's 2^53.

## 4. What the canvas reads back

This is the recognized slice (`packages/host/src/parser/facts.ts`). Write any
of these forms and the canvas sees it; write something else and the block still
compiles and runs — it just shows up with less detail.

| # | C++ form | Becomes |
|---|---|---|
| S1 | `class X : public Component` | a block (`struct`, `final`, and `microarch::`-qualified bases all match) |
| S2 | `: Component("label")` in a ctor init list | the block's label |
| S3 | `class E : public Event { … }` | a message + its payload fields |
| S4 | `Link* member;` / `Link& member;` | an out-port named `member` |
| S6 | `port->configureOut(registry.find("Y"))` | a **wired** edge to `Y` (Tier 1) |
| S6 | `port->configureOut(&y)` | a wired edge — but see the caveat below |
| S7 | `port->latency = N` / `port->setLatency(N)` | the wire's latency |
| B1 | `make_unique<E>()` … `port->send(std::move(v))` | the port emits `E` |
| B1 | `port->send(std::make_unique<E>(…))` / `port->send<E>(…)` | same |
| B2 | `static_cast<E&>(ev)` / `dynamic_cast<E&>(ev)` | the block consumes `E` |
| B2 | `void handler(E& ev)` — a **typed** handler | the block consumes `E` |
| B2 | `ev.type() == "E"` | the block consumes `E` |
| V1 | `<type> <name> [= init];` at class depth 1 | a state variable |
| H1 | `namespace NS { … }` | hierarchy — ids become dot-paths (`CPU0.IF`) |
| — | `Cycle name(const Event&)` on a Router subclass | a latency model |

Notes that matter:

- **Prefer `registry.find("Full.Id")`.** The destination of a `configureOut`
  must match a block **id** exactly. `configureOut(&y)` contributes the
  *variable* name `y`, so it only resolves when that variable happens to be
  named for the block it points at; otherwise the edge is still drawn, but with
  no destination (visible rather than silently dropped). The registry form
  names the id directly and always resolves.
- **`handler(Event&)` is excluded** from consume detection — the base dispatch
  signature is not a claim about a message type.
- **Facts in free functions are dropped on purpose.** A wiring call in a
  standalone `main()` is not attributed to any block; blocks own their wiring.
- Facts merge across files: a class declared in `inc/X.h` collects facts
  contributed by `src/X.cpp`.
- The parser scans `inc/` and `src/` (recursively) for
  `.h .hpp .hh .cpp .cc .cxx`, skipping `node_modules`, `build`, `out`.

### How an out-port becomes an edge

| Tier | Condition | Rendered |
|---|---|---|
| 1 `wired` | an explicit `configureOut` fact | solid |
| 2 `inferred` | the port's message has exactly **one** consumer elsewhere | dashed |
| 2b `unresolved` | several candidate consumers, no wiring | red, `to: null` |
| `routed` | the port is fabric-bound; a router rule resolves it per packet | orchid, `⇢ via R1` |
| 3 stub | message emitted, nobody consumes it (or no `send` on the port) | dotted |

Tier 1 always wins. If a wire you drew disappeared, check that
`configureOut` survived your edit; if an edge you expected never appeared,
check that the destination actually *consumes* the message in one of the three
B2 forms.

## 5. Recipes

**Hand-write a block the canvas can read.**

```cpp
#pragma once
#include "microarch/engine.hpp"
#include "iss_events.h"

class Probe : public microarch::Component {
  public:
    explicit Probe(microarch::Link* out = nullptr)
        : Component("Probe"), out_(out) {}

    void handler(microarch::Event& ev) override {
        if (ev.type() == "PingEvent") {          // ← consume, recognized
            ++hits_;
            if (out_ && out_->connected()) {
                auto reply = std::make_unique<PongEvent>();
                out_->send(std::move(reply));    // ← emit, recognized
            }
        }
    }

  private:
    microarch::Link* out_;                        // ← out-port, recognized
    uint32_t hits_ = 0;                           // ← state variable, recognized
};
```

Dropped into a project whose design already has a `PongEvent` consumer, that
file alone gives the canvas:

```
block recognized   true | kind leaf
consumes           [ 'PingEvent' ]
out-ports          [ 'out_ -> PongEvent' ]
state vars         [ 'hits_:uint32_t' ]
edges from Probe   [ 'out_ inferred -> Sink' ]      ← Tier 2: one consumer, so it resolved
```

It renders with a dashed border and refuses canvas edits, because it is absent
from the sidecar — see the note at the end of §6.

**Emit an addressed packet** (so router rules can sort it):

```cpp
auto ev = std::make_unique<ReadEvent>();
ev->addr = 0x8000'0000;         // matched against each rule's [lo, hi]
out_->send(std::move(ev));
```

**Originate traffic from a clock edge** (no in-flight token to inherit):

```cpp
void tick(microarch::Cycle cycle) override {
    if (cycle % 4) return;
    auto ev = std::make_unique<ReqEvent>();
    ev->token = scheduler_.mintToken();
    out_->send(std::move(ev));
}
```
The component must be registered with `scheduler.addClocked(*this)` — the
generated harness does that for traffic generators and routers.

**Give a message an honest width.** Widths come from the declared field types
(`uint64_t data[8]` costs 512 bits). When the field list can't express the
truth — a compressed payload, an unnamed header, a burst that is one logical
packet — set the override in the ✉ Messages view rather than editing
`iss_events.h`, which is regenerated.

## 6. Build and run

`▶ Run` (or `build/design <cycles>`) compiles with:

```
g++ -std=c++17 -O2 -Iinc -Isrc -I<engine>/include \
    src/iss_main_gen.cpp <hand-written top-level src/*.cpp> \
    <engine>/build/libmicroarch.a -o build/design
```

**Which files become translation units:**

- `src/iss_main_gen.cpp` — always.
- Any **top-level** `src/*.cpp` that contains **no marker** — i.e. your
  hand-written files, compiled as their own TUs.
- Generated block files are *not* TUs. They are single-file inline classes
  `#include`d by the harness, which is why they carry `#pragma once`.

Two consequences worth stating plainly:

- A hand-written `.cpp` **inside a subdirectory** (`src/CPU0/Mine.cpp`) is
  neither compiled as a TU nor included by the harness. Put hand-written blocks
  at the top level of `src/`, or include them from a file that is.
- **The harness only instantiates blocks that are in the model** (the sidecar).
  A hand-written class is parsed and drawn on the canvas, but nothing
  constructs, wires or clocks it unless the design authors it.

The run writes `iss_trace.jsonl` next to the binary; that file is what the
canvas animates.

> **Verified gotcha.** Adding a canvas block whose id equals a hand-written
> class's id does **not** adopt that file — it appends a generated class to it,
> giving you two definitions of the same class and a compile error. Give the
> canvas block a different id, or convert the file yourself by adding the
> marker region and letting the canvas own it.

## 7. Editing rules of thumb

- Inside a marker region, **edit through the canvas**. Anything you type there
  is gone at the next edit.
- Below the END marker, **write whatever you want** — router latency models, a
  custom `tick()`, helpers, the SV twin's behavior.
- `Component("<id>")` is engine identity, not a label. Renaming it renames the
  block in the registry, the harness wiring and every trace record. Rename
  through the inspector instead.
- Constructors take their out-links **positionally, in writer order**. If you
  hand-edit a generated ctor's parameter list, the harness will pass links in
  the old order.
- `setLink(const char* port, Link*)` is the stable ABI for injecting a link
  after construction; prefer it over reaching into members.
- Keep `uint64_t` addresses out of any JSON you emit yourself — write them as
  hex strings, as the trace writer does.
